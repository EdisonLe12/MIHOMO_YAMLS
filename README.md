## YAML 更新日志

### 关于 “DNS泄漏” Tips:
1. **保留 `China-IP,no-resolve`（规则默认 / 隐私与防止DNS泄漏优先）**：
   * **DNS 隐私机制**：规则匹配时不触发本地 DNS 递归解析反查，海外域名完全交由远端代理服务器进行 DNS 解析，防止本地 DNS 查询泄露、流量审计与域名污染风险，纯本地匹配消除首次建连时延。
   * **潜在分流影响**：判定完全依赖预设域名库；未收录的 CN 域名将无法触发 CN IP 判定，可能会被误分流至「漏网之鱼」并走代理（部分域名可能会出现无法加载或地区受限等问题），且其 UDP 443 会被拦截并回退至 TCP 传输。

2. **移除 `no-resolve`（可选配置 / 分流精度优先）**：
   * **识别机制**：域名未命中规则库时将触发实时 DNS 解析，通过返回的真实 IP 兜底比对，尽可能确保 CN 规则未收录的域名能准确识别走直连 (DIRECT)，避免 CN 域名或 IP 误走代理，并放行 QUIC 直连加速。
   * **潜在代价与风险**：未命中的境外域名均需向上游发起解析，存在潜在 DNS 泄露风险，且每次解析会引入额外的网络往返时延 (RTT)，略微增加海外连接首次握手时间。

### 二、`G&A-Push` 策略组使用说明（代理 vs. 直连）

*说明：本组仅覆盖 Google FCM 与 Apple APNs 两条系统级推送通道；Android 国内应用使用厂商自有推送通道，不在本组分流范围内。*

**1. 选择「代理」**
* **作用**：使 FCM 长连接经境外节点建立，恢复 Android 海外应用的后台推送；使 APNs 长连接经稳定出口维持，降低其被本地网络 NAT 超时回收后假死、导致 iOS 海外应用（如 Telegram、X）锁屏漏通知的概率。
* **注意（国内 App 推送可能异常）**：iOS 国内应用（如微信）的通知同样经 APNs 下发，原本直达国内苹果节点；本组选代理后将一并绕行境外节点。若所选节点故障或被切换，长连接会断开重建，期间国内应用的通知也会延迟或漏收。
* **Tips**：选代理时请指向固定顺位的「故转」组或稳定单节点，切勿指向会频繁变更节点的 Smart/自动测速类策略组。

**2. 选择「直连」**
* **作用**：推送流量直接经本地运营商网络出站，iOS 国内应用的通知直达国内苹果节点，链路最短、延迟最低，且完全不受代理节点可用性影响。
* **注意（海外 App 推送可能异常）**：
  * **Android 端**：国内网络下 Google FCM 直连被阻断，长连接无法建立，海外应用退至后台后将收不到通知；系统反复尝试重连还会额外增加耗电。
  * **iOS 端**：受运营商对闲置 TCP 连接的 NAT 超时回收机制影响，锁屏时间过长后 APNs 长连接可能假死，表现为海外应用“锁屏不响、解锁或打开 App 后集中弹窗”。
* **Tips**：以 iPhone 与国内应用为主、无 Android 海外推送需求时，直连为更稳妥的选择。
